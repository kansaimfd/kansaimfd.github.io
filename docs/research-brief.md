# 施設情報の調査指示書

施設1件を公式サイトで調べ、**書いてあることだけ**を記録するための手順書。
調査エージェントはこのファイルを読んでから作業する。

## 最重要の原則

> **公式サイトに書いてあることだけを記録する。書いていないことは記録しない。**

このデータは以前ローカルLLMで自動収集したが、精度に問題があり作り直している。
もっともらしい値を埋めることが、この作業で最も避けたい失敗である。

- ページに書いていない項目は**キーごと省略する**（推測で埋めない）
- 「たぶんこうだろう」で書かない。分からないものは分からないままにする
- Wikipedia や第三者サイトは使わない。**公式サイトのみ**
- 記載を見つけたら、そのページのURLを `出典` に必ず残す

## 手順

1. 与えられた施設の公式URLを WebFetch で開く
2. 施設概要 / 施設案内 / 貸室案内 / アクセス / 利用料金 などのページを辿る
   （トップページだけでは情報が足りないことがほとんど）
3. 下記のスキーマに沿って、**確認できた項目だけ**を書き出す
4. 指定された出力ファイルに YAML で保存する

WebFetch は3〜8ページ程度まで。見つからなければ「見つからなかった」と報告してよい。

### 実際によくある誤りの型（10施設の調査で判明）

登録データは**住所5割・最寄駅5割・URL8割が誤っていた**。専門的な数値より、
まずこの3つを疑うこと。

**① 徒歩分数の起点が駅ではない**
「金剛駅→バス→◯◯バス停下車、**徒歩8分**」の徒歩8分は**バス停からの徒歩**であって
駅からではない（すばるホール）。どこからの距離・分数なのかを必ず確認する。

**② 駅からの距離ではない数値**
「阪神高速 堺出口より約450m」は**高速道路の出口**からの距離（フェニーチェ堺）。
`駅距離` に入れてはいけない。

**③ 隣の施設の数値**
「バス6分、◯◯下車、徒歩約8分」の徒歩8分が、調査対象ではなく
**隣接する別施設まで**の数値だったことがある（伊吹薬草の里文化センター）。

**④ そもそも最寄駅が違う**
登録された駅が公式サイトに一言も出てこないことがある（LICはびきの・ひこね市文化プラザ）。
**公式が「最寄り駅」と呼んでいる駅**を採ること。

**⑤ 同じ運営者の別施設と混ざっている**
サイトを共有している施設群では、隣の施設の住所・アクセスが紛れ込んでいることがある
（ローズ文化ホールに文化芸術センターの住所が入っていた）。
公式サイトが**その施設のページで**何と書いているかを見ること。

**⑥ 施設名・URLと住所が別々の施設を指している**
`弥生の風ホール` は名前とURLが和泉市の施設、住所と最寄駅が泉佐野市の別施設を指していた。
**名前で調べた施設と、住所で調べた施設が一致しない場合は、そこで止めて報告する。**
どちらが正しいかを勝手に決めない。片方だけを信じて調査を進めると、
まるごと別施設のデータが出来上がる。

**⑦ そもそも貸室ではない（練習場に多い）**
`practice.yaml` には、楽器店・音楽教室・個人サロンが混ざっている。時間貸ししておらず、
レッスン受講者だけが使える施設や、そもそも部屋を貸していない店舗がある
（フルート・アンシャンテは骨董フルート専門店のサロンで、貸室ではなかった → 削除した）。

**練習場は「部屋を時間単位で借りられるか」を最初に確かめること。**
「1時間◯円」「利用料金」「予約」といった貸室の記載が公式サイトに一つも無ければ、
設備を調べる前に**その旨を報告する**（勝手に削除せず、判断はユーザーに委ねる）。
教室の生徒限定・会員限定の場合は、`楽器制限` ではなく報告で伝えること。

**姉妹サイトの内容が混ざって返ってくることがある。** 西淀川区民会館のページを取ったら、
同じ運営者の別サイト（西淀川区民ホール）の料金表が返ってきた例がある（取り直すと直った。サイト側のキャッシュ混線）。
同じドメインに姉妹館が並んでいるサイトでは、**取ったページが本当にその施設のものか**を毎回確かめること。
ページ内の施設名、schema.org の `"@id"`、住所・電話を見れば判別できる。数値は2回取って一致を確認する。

### WebFetchの要約自体が誤ることがある

WebFetch は取得したページを別のモデルで要約して返すため、**そこで事実が捏造されうる**。
実際に、同じページの住所を2回とも別々の地名に幻覚した例がある（ユーベルホール）。

**住所・客席数など重要な値が1ページでしか確認できない場合は、別のページでも裏を取ること。**
複数ページで一致すれば信用してよい。食い違ったら、より新しい／公式性の高いページを採り、
食い違いの事実を備考に残す。

**住所は WebFetch の要約で確定しないこと。** 幻覚が集中しているのが住所で、実例が3件出ている。

| 施設 | WebFetch が返した住所 | 実際の記載 |
|---|---|---|
| ユーベルホール | 2回とも別々の地名 | — |
| アスピアやましろ（木津川市サイト） | 「南丹市園部町」「JR園部駅」 | 木津川市山城町平尾前田24 |
| 神戸芸術センター | 3回で「栄町通」「磯上」「北長狭通」 | 熊内橋通7-1-13 |

いずれも**もっともらしい実在の地名**を返してくるので、要約だけ見ても誤りに気づけない。

**住所・駅名・数値は `curl` で生HTMLを取って原文を確認すること。**
文字化けする場合は `iconv -f SHIFT_JIS -t UTF-8` を通す。
タグを落として読むなら `sed -e 's/<[^>]*>/ /g'` で十分。

#### `駐車場` は「来場者が使える台数」

主催者専用・障害者用・搬入用しかない施設は **`0`** を書く（台数を書かない、ではなく 0）。
一覧の「駐車場あり」の絞り込みは台数が1以上かどうかで判定するので、
専用枠の台数を入れると「車で行ける施設」として出てしまう。実際に使える枠の内訳は備考に書く。

> 「催し等に来場される方のための駐車場はありません」（身障者用のみ事前予約制） → `0`
> 「来場者用の駐車場はなし」（大ホール主催者専用の地下4台のみ・要予約） → `0`
> 「駐車場がありませんので、車によるご来場は固くお断りしています」 → `0`

複合施設で共用の駐車場は台数を書いてよいが、**共用であることを備考に必ず書く**
（アラベスクホールの314台はウェルネスパーク全体、キセラホールの382台は文化棟＋福祉棟の共用）。

### 失効したドメインが別サイトに転用されていることがある

**開けたからといって、その施設のサイトとは限らない。** 施設が使わなくなったドメインを
第三者が取得し、無関係な内容を載せている例がある。

> SAYAKAホールの登録URL `sayaka-hall.jp` は、2024年6月作成の英語WordPressサイトになっていて、
> 難波駅周辺の賃貸物件を紹介していた。トップに施設名が一度も出てこない。

**見分け方**: ページ内に施設名が一度も出てこない、`inLanguage":"en-US"` のような
日本の公共施設ではありえない言語設定、扱っている話題が施設と無関係。
この状態は **404 より危険**で、リンク先として残すと利用者を無関係なサイトに送ってしまう。
見つけたら報告に明記し、現行の公式サイトを探し直すこと。

（`node scripts/audit-urls.mjs` で全レコードのURLを一括検査できる。
到達不可のものと、ページ内に施設名が出てこないものを一覧する）

### サイトそのものが消えている場合

現行サイトも後継サイトも見つからないときは、**Wayback Machine（`web.archive.org`）を
最後の手段として使ってよい**。ただし次を必ず守ること。

- **出典URLはアーカイブのURLをそのまま書く**（`https://web.archive.org/web/<timestamp>/...`）。
  現行サイトの記載であるかのように書かない
- **備考に、最後の生存キャプチャの日付と、それ以降どうなっているかを書く**
- 数値・住所は、**保存座標や最寄駅との距離で裏が取れるかを確かめる**。
  アーカイブが古いほど、単独では信用できない
- **施設が今も存在するのか自体を疑い、報告に書くこと**

（フルート・アンシャンテは2021-04-18が最後の生存キャプチャで、以降は403。
そこに書かれていた住所は保存座標から251mで、登録住所の3,543mより明らかに妥当だった。
アーカイブの住所を採れたのは、座標と駅からの距離という**別の根拠と一致した**からである。）

**アーカイブのURLに日時を入れても、その日時の版が返るとは限らない。** Wayback は近い日付の
別の版に黙って転送することがある（まつむし音楽堂で 2024-12-05 を指定したら 2023-12-03 の版が返り、
閉館告知が載っていなかった）。確かめるときは次の2段で取ること。

1. CDX API で実在する版の日時を一覧する
   `https://web.archive.org/cdx/search/cdx?url=<ドメイン/パス>&from=2024&output=json&fl=timestamp,original,statuscode`
2. 日時の直後に `id_` を付けて**原本そのもの**を取る（ツールバーの差し込みもなくなる）
   `https://web.archive.org/web/20241205094249id_/http://www.ladies.jp/matsumushi/`

### 登録URLが生きていても公式とは限らない

登録URLが開けたからといって、それが**施設自身のサイトとは限らない**。
観光協会・コンベンションビューロー・自治体の施設紹介ページのことがある
（ポートピアホールの登録URLは神戸コンベンションビューローの紹介ページだった）。

**運営者自身が出しているページを探すこと。** 見分け方は、貸館の申込方法・利用料金・
附属設備一覧といった「借りる人向けの情報」があるかどうか。紹介ページには普通これが無い。
**入居している商業ビルのサイトのことがある。** 六甲道勤労市民センターの登録URL
（`meinrokko.com`）は「メイン六甲」という駅直結ビルのショッピングサイトで、
本文に施設名が一度も出てこず、4・5階のテナント名として載っているだけだった。
施設のページは運営者（公益財団法人神戸市民文化振興財団）のサイトにあった。
**登録URLの本文中に施設名が出てこないときは、そのサイトは施設のものではない。**

**`<title>` に無関係な文字列が入っていることがある。** 大阪市コミュニティ協会の都島区民センターの
ページは、全ページの title が「まるよし精肉店 都島区民センター施設概要」のようになっていた
（同じサイトの他館は正常で、この施設のページだけの汚染）。本文・住所・電話・指定管理者の記載は
正しかったので値は採れる。**title だけで別サイトと判断せず、本文で確かめること**（逆に、
URL監査が「別サイトの疑い」と出すのもこの type の理由であることが多い）。

**逆に、施設名と何の関係もないドメインでも公式のことがある。** 甲東ホールの登録URLは
`futaba-kagaku.co.jp/koutou/` で、一見すると無関係な化学会社のドメインに見えるが、
これは**指定管理者（株式会社双葉化学商会）の自社サイトのサブディレクトリ**で、
西宮市の施設ページからも「指定管理者作成のホームページ（外部サイト）」としてリンクされていた。
料金表・申込方法・附属設備一覧がそろっているので、判断の基準は前段と同じでよい
（**借りる人向けの情報があるか**）。ドメイン名で切り捨てず、中身を見ること。
自治体側に施設ページがあるときは両方を突き合わせ、**食い違ったら新しい方**を採る
（甲東ホールは指定管理者サイトが「アプリ甲東4階」、市の2024年更新ページが「4・5階」だった）。

**個別ページが存在せず、一覧ページ＋PDFが実体のことがある。** 西宮市立の公民館23館には
館ごとのページが無く、一覧ページから各館の案内PDFに直接リンクされているだけだった。
この場合、登録URLを差し替える先が無いので**一覧ページのまま据え置く**のが正しい。
部屋・備品・アクセスはすべてPDF側にしかない。

**1つの事業者が複数の施設を1ドメインにまとめていることがある。** 瀬楽（大阪市西成区）は
サイトのリニューアルで `seraku-studio.co.jp` → `seraku-st-dr.com` へ移ったが、
新ドメインは「瀬楽スタジオ」「瀬楽ホール」「バンドスタジオ」の**3施設を束ねたサイト**で、
瀬楽ホールとバンドスタジオは**別住所・別電話番号**だった。
**URLはトップではなく、その施設のページまで下げて記録すること。**
トップを記録すると、後の調査で別施設の値を拾う。


**大阪市の施設予約システムは、curl で取ると全施設に同じダミーの部屋一覧を返す。**
`shisetsu-osaka.jp/shisetsu-nw/akijokyo.html?scd=<施設コード>` の静的HTMLは、
施設コードを変えても「ホール 549.5㎡／定員700人」「第1〜第6会議室」「和室1・2」と**一字一句同じ**内容で、
実データはJavaScriptで後から差し込まれる。**このページから部屋名・面積・定員を採ってはいけない。**
予約システム系のページは、別の施設コードでも同じ数字が出ないかを確かめてから使うこと。


### 登録URLに到達できない場合

**登録されているURLは古いことがある。** 移転・ドメイン変更・410 Gone は珍しくない。

- 同じホストの別サブドメイン（`www` → `www1` など）を試す
- **施設名で検索して現行の公式サイトを探す**
- 旧サイトが部分的に生きている場合、そこに残る情報は**古い可能性が高いので採用しない**
- 現行の公式URLを見つけたら、`URL:` フィールドに記録して報告に明記する
  （登録側のURL更新が必要なため）

### PDFを必ず確認する（最重要）

**備品の情報はHTMLページにほぼ書かれていない。料金表のPDFの中にある。**

これは実地調査で確認済みの事実で、PDFを開くかどうかが取得量の最大の差になった。

| 探すもの | 典型的な在り処 |
|---|---|
| ピアノの有無・種別・メーカー | **附属設備利用料金表PDF**（「ヤマハピアノC-7 …」のように備品名で載る） |
| 譜面台の有無・本数 | 同上（「譜面台 1台 100円／20台まで」） |
| 打楽器などの貸出楽器 | 同上（「【打楽器】ティンパニー、ドラムセット…」） |
| 舞台寸法・客席数 | 施設概要ページ、または舞台図面PDF |

利用料金ページに「附属設備利用料金」「備品使用料」「舞台設備」等のリンクがあれば**必ず開く**。

**PDFの読み方**（WebFetch はPDFの中身をうまく返さないことがある）
- WebFetch がバイナリで取得したら、ファイルに保存して **Read ツールで画像として読み取る**
- それでも読めなければ `pdftoppm` でPNGに変換して Read する。
  図面の細かい寸法は `-r 300` 程度の解像度を指定しないと読めない

**PDFとは限らない。** 附属設備料金がHTMLの表で書かれている施設もある（ひこね市文化プラザ）。
PDFが見つからなければHTML側の備品一覧・料金表を探すこと。

**公営施設は条例・規則が使える。** 公式サイトに備品の記載がなくても、
自治体の「◯◯条例施行規則」の別表に附属設備使用料が載っていることがある（伊吹薬草の里文化センター）。
公的な一次資料なので出典として十分。

**舞台図面PDFから寸法が読めることがある。** 「P.A. W12710」のような寸法線は
プロセニアム開口幅12,710mm＝12.71m を意味する（LICはびきの）。
ただし図面に寸法が入っていないことも多い。その場合は無理に読み取らない。

なお `料金URL` には、**PDFの直リンクではなくPDFをリンクしている親ページ**を記録する。
PDFのファイル名にハッシュや年度が入っていることが多く、直リンクはすぐ切れるため。

### これまでの調査で分かっているサイトの傾向

- **大阪市コミュニティ協会（`osakacommunity.jp`）**: 施設のページは `/<施設名>-center/`・`/<施設名>-hall/`
  の形（例 `/chuo-center/`・`/konohana-hall/`・`/miyakojima-center/`）。
  `/<区名>/` は**支部協議会（地域団体）のページで施設のページではない**（`/branches/<区名>/` に転送される）。
  旧 `/<区名>/sisetu.html` からは現行ページに転送されるので、転送先を `URL` に採ること。
  なお平野区民ホールだけは協会サイトから消え、指定管理者の個別ドメイン `osaka-hirano-kumin.jp/hall/` にある
- **HTTP 200 でも中身が空のことがある。** 西区民センターの旧ドメインは全パスが本文1バイトを返した
  （WordPress が壊れて放置されている）。ステータスコードだけで生きていると判断しないこと
- **User-Agent なしの curl を 403 で弾くサイトがある**（江坂シャロームホール）。403 が出たらブラウザの
  UA（`-A 'Mozilla/5.0 ...'`）を付けて取り直す。それでも 403 なら本当に閉じている
- **URL監査の「別サイトの疑い」は、施設が愛称で名乗っていると誤検知になる。** たかいし市民文化会館の
  公式サイトは複合施設の愛称「アプラたかいし」を title にしていて、施設名の一致率が33%しかなかった。
  meta keywords に「たかいし市民文化会館」とあり同じ施設だった。疑いが出たら、中身を見て確かめること
- **指定管理者が替わるとサイトごと替わる。** 吹田市の市民センター群は `suitacc-ogbc.jp` から
  `suitacc-klp.jp` に移り、旧ドメインは DNS ごと消えていた（ドメインの末尾が管理会社の略称）。
  神戸市の勤労会館系（`kobe-kinrou.jp`）も証明書が失効し、施設ページは神戸市民文化振興財団の
  `kobe-bunka.jp` に移っていた。**公共施設のURLが死んでいたら、まず現在の指定管理者を調べる**と早い
- **公式サイトがAIサイトビルダーのドメインに置かれていることがある。** 城東区民センターは指定管理者の
  交代で `osakacommunity.jp/joto-center/` が410になり、大阪市の公式ページが
  `jotocenter-xxxxxxx.manus.space` へリンクしていた。**市の公式ページからリンクされていること**と
  施設名・住所・電話の一致を確かめれば公式として使ってよいが、ドメインが変わりやすい点は備考に残す
- **兵庫県立芸術文化センター**: `www.gcenter-hyogo.jp` は meta refresh のみ。実体は `www1.gcenter-hyogo.jp`
- 検索結果に出てくるURLが 410 でも、それは検索インデックスが古いだけのことがある

### 住所の誤りは「町名の一部が落ちている」形が多い

登録住所が誤っている場合、まるごと別の住所ということは少なく、**町名から文字が抜けている**
ことのほうが多い。番地は合っているので、原文と並べないと気づきにくい。

| 登録 | 公式 | 抜けていたもの |
|---|---|---|
| 大阪市中央区**船場**1丁目4-11 | **南**船場1-4-11 | 「南」 |
| 尼崎市**塚口**3丁目39-7 | 塚口**町**3丁目39-7 | 「町」 |
| 京都市伏見区京町南35-1 | 京町南**七丁目**35番地の1 | 「七丁目」 |
| 京都市右京区太秦安井西裏町6 | 太秦安井西裏町**11番地の**6 | 「11番地の」 |
| 大阪市阿倍野区阿倍野元町18 | 阿倍野元町18**-40** | 「-40」 |

いずれも**実在する別の町名**になってしまうのが厄介なところで（大阪市中央区には船場中央が、
尼崎市には塚口本町・南塚口町がある）、住所だけを見ても誤りと分からない。

**国土地理院のジオコーディングが番地まで解決できない住所は、この脱字を疑うこと。**
公式の原文を1文字ずつ照らし合わせ、`番地以下` に丁目・町名を省略せず書く。

**座標が誤った住所から振られていることがある。** 住所の誤りに対して座標はたいてい正しいが、例外がある。
保存座標が**登録住所のジオコード結果とほぼ一致する（数m〜十数m）**なら、その座標は住所から機械的に
振られたもので、住所が誤っていれば座標も一緒に誤っている（小田南生涯学習プラザ・コスモホール）。
住所を直すときは、**保存座標と登録住所のジオコードの距離も測る**こと。近すぎたら座標も疑う。

### 登録名が部屋名で終わっていることがある

「神戸市立葺合文化センター**大ホール**」のように、登録名の末尾が施設内の1室の名前になっていることがある。
公式の施設名は「葺合文化センター」で、大ホールはその中の貸室だった。
**施設名と部屋名の区別を確かめ、施設名に部屋名が混ざっていれば報告すること**（同じ形が他にもありうる）。

### 施設名が改称されていることがある

登録名が古いままのことがある。**公式が自分をどう名乗っているかを見て、違えば報告すること**
（施設名は出力スキーマに含めないので、記録はせず報告だけでよい）。

- 「神戸市立東灘区民センター」→ 令和2年4月に「東灘区文化センター（うはらホール）」へ改称
- 「高槻現代劇場」→「高槻城公園芸術文化劇場」へ改称
- 「大東市立総合文化センター サーティホール」→ 公式の名乗りは「大東市立文化ホール（サーティホール）」で、
  総合文化センターはそれを含む建物の名前だった
- 「神戸市立六甲道勤労市民センター」→「神戸市立灘区文化センター」へ改称
  （公式サイトは新名称しか出しておらず、旧名称はページ内に一度も出てこない。
  建物・階数・電話番号が同一であることで同じ施設だと確かめられた）

**建て替え・別施設への移転と、単なる改称は違う。** 沿革・お知らせに
「名称変更」と書かれていれば同じ施設なので、IDはそのままでよい。
公式が「新しい施設」と言っている場合は、別施設の可能性があるので報告に明記すること。

**近くへの移転は、同じ店・施設として扱ってよい。** 島村楽器の梅田ロフト店は、2025年1月に閉店し、
同年8月に約90m離れた「チャスカ茶屋町7F」で梅田茶屋町店として再開していた。店舗ページのURL・電話番号が
引き継がれ、公式が「移転」と書いているので同じIDのまま名前・住所・建物を改め、座標は新住所から引き直した。
**座標を動かすときは、公式の徒歩分数と駅座標マスタで方角・距離が合うことを必ず確かめる**（独立した根拠が要る）。
公式が「新しい施設」と言っている場合や、遠くへ移った場合は、止めて報告すること。

**ネーミングライツの愛称は改称ではない。** 期間が切れれば元に戻るので、
**期間が明記されている愛称は施設名として採らず、報告と出典の備考に書くだけにする**
（芦屋市民会館の「ルネサンス クラシックス芦屋ルナ・ホール」は令和4年4月〜令和9年3月の期間限定）。
一方「東リ いたみホール」「DMG MORI やまと郡山城ホール」「あましんアルカイックホール」のように、
**施設が自分の名前として常用していて期間の記載が前に出てこないもの**は施設名として使ってよい。
迷ったら現状の登録名を変えず、公式の名乗りを報告すること。

**冠称つきの名乗りが標準になっている系列がある。** 大阪市コミュニティ協会の施設は
「J:COM中央区民センター」「NORBDENCE福島区民センター」「此花区民一休ホール」「藤井組 大正会館」のように
スポンサー名を冠した名乗りが普通で、**公式サイトに期間が書かれていない**。
期間が確かめられない以上、指示書の方針どおり**施設名には採らず**、報告と出典の備考に書くだけにする。
検索で契約期間が見つかっても、公式サイトに無いなら採らないこと（更新されていることが多い）。

### 住所の照合（記録はしないが報告する）

`住所` は出力スキーマに含めないが、**公式サイトに記載の住所が指示された住所と違う場合は報告すること。**

登録住所は**5〜6割が誤っている**。検証した12件のうち、市区町村レベルから違うもの（豊岡市→加古川市）、
町名が違うもの（鈴蘭台東町→西町、北八木町→小房町）、別施設の住所が入っていたものが出ている。
**一方で座標はおおむね正しい。** 元データを作ったローカルLLMが、座標は施設名から地図サービスで引き、
住所は別に生成していたためと見られる。

そのため**住所が違ったら、その旨だけを報告して先に進むこと**。
「座標に合う住所」を探しにいかない。座標と住所のどちらが正しいかは、こちらで判断する。

**公式の住所が登録と一致したのに座標が合わない場合**は、報告に
「公式が書いている最寄駅と徒歩分数」を必ず添えること。徒歩分数が第3の基準になる。
（野洲文化ホールでは、住所のジオコード結果が駅から53mだったのに対し保存座標は217mで、
公式の「駅から徒歩3分」と合うのは保存座標のほうだった。大きな番地ブロックでは
ジオコーディングが代表点を返すため、住所が正しくても座標がずれて見える。）

**「東へ徒歩5分」のように方角が書かれていれば、それも報告に含めること。**
距離と方角の両方が合えば座標をほぼ確定できる（やまなみホールは、小字までジオコードが
解決できず住所からは判定不能だったが、保存座標が大河原駅の東376mにあり
公式の「大河原駅から東へ徒歩5分」と距離・方角の両方で一致した）。

### 練習場に本格的なホールがあることがある

`practice.yaml` の施設が、固定席と舞台を備えた本格的なホールを持っていることがある
（米原ルッチプラザの「ベルホール310」は固定席310・間口13m・スタインウェイ常設）。

**練習場のスキーマには `舞台幅` / `舞台奥行` / `ホール種別` / `親子室` が無い。**
書いてあっても記録できないので、**出典の備考に原文のまま引用して報告に挙げること**
（分類を変えるかどうかはユーザーが判断する）。`客席数` は練習場でも記録できる。

### 舞台幅が「16.6〜18.0m」のように幅で書かれている場合

可変プロセニアムのホールでは開口が範囲で書かれている。**最大値を採り、
`備考` に「可変（◯〜◯m）」と原文を残す**。範囲だからと記録を見送らないこと。
利用者が知りたいのは「何が入るか」なので上限が実用的な意味を持つ。

同様に `舞台奥行` が「14.4m（音響反射板設置時10.6m）」のように書かれている場合は、
**反射板を使わない素の値**（14.4m）を採り、備考に反射板使用時の値を書く。

**「幅14.5m〜」のように上限が書かれていない場合**は、書かれている値（14.5）を採り、
備考に「上限の記載なし」と明記する。上限を推測して埋めないこと。
この場合に記録されるのは最小値なので、備考が無いと後から誤読される。

### 数値には根拠の原文を必ず引用する

`客席数` `面積` `定員` `舞台幅` `舞台奥行` `駐車場` `譜面台数` `楽屋収容人数` を記録するときは、
**その数字が公式ページでどう書かれていたかを、出典の `備考` に原文で引用する。**

```yaml
    備考: 「座席数1704」と記載。別ページに「客席 定員1,845名」の記載もあるが定員なので採らない
```

似た顔をした値の取り違え（座席数と定員、間口と主舞台寸法など）は、
後から検証できなければ発見できない。**引用があれば、ページを開き直さずに検証できる。**

## 出力形式

指定されたパスに、**確認できたフィールドだけ**を含む YAML を書く。
ID と 施設名 は照合用に必ず含める。

> **施設1件のマッピングとして書くこと。先頭に `- ` を付けてリストにしないこと。**
> 元データ（`data/facilities/*.yaml`）は施設の配列だが、この出力は1施設ぶんのマッピングである。

```yaml
# 以下は書式を示すための**架空**の例。施設名も数値も実在しない。
# 値をここから借りてこないこと
ID: 9999
施設名: 例示市民会館
築年月: 1988-03
駐車場: 60
申込URL: https://example.com/rental/
料金URL: https://example.com/price/
最寄駅:
  - 路線: [例示電鉄本線]
    駅: 例示中央駅
    出口: 北口
    駅徒歩: 7
部屋:
  - 部屋名: 大ホール
    ホール種別: 多目的
    客席数: 1234
    舞台幅: 16
    舞台奥行: 11
    ピアノ有無: true
    ピアノ種別: グランド
    ピアノメーカー: スタインウェイD-274・ヤマハCFX
    パイプオルガン: true
    オルガン製作者: 例示オルガン社（40ストップ）
    譜面台貸出: true
    譜面台数: 50
    楽屋収容人数: 42
出典:
  - URL: https://example.com/about/
    確認日: '2026-09-02'
    項目: [客席数, 舞台幅, 舞台奥行]
    備考: 「1,234席（うち車椅子6席）」「間口16m・奥行11m」と記載。楽屋の収容人数は記載なし
```

**このファイルに書いたフィールドは「公式に記載があった」ことを意味する。**
確認できなかったフィールドは書かない。


### YAMLが壊れる2つの書き方

備考や楽器制限に公式の原文を写すとき、**クォートしない平文のまま**書くと次の2つで壊れる。
迷ったら値全体をダブルクォートで囲むこと。

1. **「コロン＋半角空白」** … `備考: 駐車場: 0 とした` は、2つ目の `: ` がマッピングの区切りと解釈されて
   `bad indentation of a mapping entry` になる。「駐車場の台数は0と記録した」のように言い換えるか、クォートする。
2. **「空白＋#」** … `ピアノメーカー: ベーゼンドルファー model170 #45523` は、`#` 以降がコメントとして
   捨てられる（シリアル番号が消える）。**全角の＃にするか、値をクォートする。**

どちらも公式の原文をそのまま写したときに起きる。書いたあとは必ず js-yaml でパースして確かめること。

## フィールド定義

### 施設レベル（共通）

| フィールド | 型 | 備考 |
|---|---|---|
| `URL` | string | **現行の公式URL**。登録URLが古い場合のみ書く |
| `申込URL` | string | 利用申込・予約案内のページ |
| `料金URL` | string | 利用料金のページ（PDF直リンクではなく親ページ） |
| `TEL` | string | |
| `開館時間` / `閉館時間` | string | `"09:00"` 形式。クォート必須 |
| `休館日` | string | 原文のまま |
| `駐車場` | number | 台数。下記参照。**「駐車場はありません」と明記されていれば `0`**（省略＝未調査） |
| `最寄駅` | 配列 | 下記参照 |
| `貸館` | マッピング | **借りられない場合のみ**。下記参照 |
| `出典` | 配列 | 必須。下記参照 |

#### `貸館` — 休止・終了

改修・建て替え・事業終了で**現在借りられない**施設だけ書く。通常営業なら書かない。

```yaml
貸館:
  状態: 休止        # 休止（一時的・再開予定あり） / 終了（再開しない）
  開始: '2026-07'   # 任意
  再開: '2028-03'   # 任意。休止のみ。未定なら省略する
  理由: 大規模改修工事
```

- 「◯年◯月をもって受付を終了しました」→ `終了`
- 「◯年末で終了」「◯月末をもって閉館」→ `終了` / 開始は**その翌月**（借りられなくなった最初の月）。
  「2024年末で終了」なら `2025-01`
- **まだ始まっていない休止は書かない。** 「令和9年1月4日〜3月31日 ホール利用停止」のような予告は、
  調査日がその前なら今は借りられるので `貸館` を立てない。**必ず調査日と比べること**
  （西宮市勤労会館で、半年先の休止を 休止 と書いてしまった例がある）。予告は出典の備考に原文で残し、報告に挙げる
- 「令和7年11月から休館しています。再開は令和8年9月以降」→ `休止` / 開始 `2025-11` / 再開 `2026-09`
- **建物が開いていても貸館だけ終えていることがある**（龍谷大学 響都ホール）。
  判断の基準は「今から借りられるか」であって、建物が開いているかではない
- `終了` に `再開` は書かない（ビルドが止まる）
- **一部の部屋だけ休止・終了しているときは、施設ではなく `部屋` の中に書く。**
  施設側の `貸館` は「全室が対象」の意味になる。
  あましんアルカイックホールのように、1施設の中で
  「大ホール＝耐震工事で休止／中ホール＝通常営業／小ホール＝貸出終了」と分かれることがある

### 施設レベル（コンサートホールのみ）

| フィールド | 型 | 備考 |
|---|---|---|
| `築年月` | string | `YYYY-MM` 形式。開館年月 |

### 最寄駅

```yaml
最寄駅:
  - 路線: [Osaka Metro御堂筋線, Osaka Metro中央線]   # 同一駅の複数路線は並べる
    駅: 本町駅                                       # 「駅」を付ける
    出口: 23号出口                                   # 書いてあれば
    駅徒歩: 5                                        # 公式が徒歩分数で書いている場合
    駅距離: 800                                      # 公式が距離(m)で書いている場合
```

- **`駅徒歩` と `駅距離` は、公式が書いている方だけを書く。**
  「南へ800m」なら `駅距離: 800`。「徒歩10分」なら `駅徒歩: 10`。両方あれば両方。
  **徒歩分数を距離から自分で計算しない**（ビルド時に自動で補完される）
- バスの場合は `路線: [◯◯バス]` `駅: ◯◯バス停` と書く
- **駅名に事業者名を付けない。** 公式が「阪神尼崎駅」「JR川西池田駅」と書いていても、
  `駅` には「尼崎駅」「川西池田駅」と書き、事業者・路線は `路線` に入れる。
  駅座標マスタ（`data/stations.json`）が事業者名なしの駅名で引けなくなり、
  徒歩分数の検算が効かなくなる（同名駅は路線で区別されている）。
  **ただし「近鉄郡山」「近鉄八尾」のように事業者名込みが正式な駅名のこともある。**
  剥がす前に `data/stations.json` を引いて、どちらが登録されているか確かめること
- **`路線` には事業者名ではなく路線名を書く。** 公式が「阪急電車」「阪神電車」「JR」としか
  書いていない場合は、`data/stations.json` でその駅の路線を引いて補ってよい
  （出典は国土数値情報なので推測ではない）。大阪駅のように路線が多すぎて特定できない場合は、
  公式の表記のまま残す

### 部屋（施設内の各ホール・各練習室）

**複数のホール・練習室がある施設は、必ず全室を配列で書く。**
これが今回の調査で最も重要な改善点。現状は多くの施設が1室しか登録されていない。

コンサートホール:

| フィールド | 型 | 備考 |
|---|---|---|
| `部屋名` | string | 大ホール / 小ホール など |
| `ホール種別` | string | `音楽専用` / `多目的` / `小ホール・サロン`。判定手順は後述 |
| `客席数` | number | **「座席数」であって「定員」ではない**。下記の注意を読むこと |
| `舞台幅` / `舞台奥行` | number | m。**`舞台幅` はプロセニアム開口（間口）**。下記の注意を読むこと |
| `楽屋収容人数` | number | 楽屋の**合計収容人数**。「大48名1室・中24名2室・小4名4室」なら 112 |
| `親子室` | boolean | 下記の注意を読むこと。**取りこぼしが多い** |

#### 客席数：「座席数」と「定員」を混同しない

公式サイトは同じホールについて、ページごとに違う数字を書いていることがある。

> 実在の施設で見つかった例（施設名も数値も架空に置き換えてある。値をここから借りてこないこと）
> 施設紹介ページ … 「**座席数**◯◯◯◯という規模は…」
> 貸館案内ページ … 「客席 **定員**◯,◯◯◯名」
>
> 同じホールなのに、片方は「座席数」、もう片方は「定員」と書いている。

**どちらも正しく、指しているものが違う。** `定員` は立見・合唱席・オーケストラピット席などを
含む収容人数で、`座席数` とは別物。**`客席数` に入れるのは「座席数」の方**。

「定員」しか書かれていない場合は `客席数` を**書かない**。

**ただし内訳が全部「席」で書かれ、合計と一致するなら採ってよい。** 語が「定員」でも中身は座席数である。

> 「定員：1,000席（1階席759席、2階席241席）※車イス席5席を含む」 → 759＋241＝1,000 なので採る
> 「◯◯席（ピット席104席を含む）」 → 採る
> 「収容人員1,220人（固定席1,210席、車椅子席10席）」 → 採る
>
> 「客席 定員1,845名」（内訳なし） → **採らない**。立見・合唱席を含みうる

判断の基準は語ではなく**内訳が席で説明されているか**。内訳の無い「定員◯名」だけは採らない。

#### 親子室・多目的鑑賞室の席は 客席数 に含めない

数字が2つ併記されているとき、**差が親子室席なら小さいほうを採る**。親子室は別室なので、
そこの席数を足した数を客席数にすると施設どうしを比較できなくなる。

> 「固定席1,202席（ピット154席を含む）車いす席6席、親子室16席」／概要ページ「1,224席」
> → 1,224 は 1,202＋6＋16。**1,202 を採る**
> 「固定席974席、車椅子席10席、多目的鑑賞室2室16席」／概要PDF「1,000席」
> → 1,000 は 974＋10＋16。**974 を採る**（多目的鑑賞室は親子室に相当する別室）

車椅子席は含まれていてよい（「1,220人（固定席1,210席、車椅子席10席）」のように
総数に組み込んで書く施設が多く、そこだけ引き算すると公式にない数字になる）。
**足し算・引き算をして公式にない数字を作らないこと。** 公式が書いている数のうち、
親子室席を含まないものを選ぶ。

**内訳に親子室席が明示されているなら、それを引いた数を採ってよい。** 公式に「親子室を含まない数」が
書かれていなくても、内訳が全部書かれていれば、そこから親子室分を引くのは捏造ではない。

> 「座席数359席／1階席224席および車いす席4席／2階席124席および親子室7席」
> → 224＋4＋124＝**352 を採る**（アルカスホール）
> 「153席（うち車椅子席3席、親子席3席）」 → 153−3＝**150 を採る**（たかいし市民文化会館 小ホール）

引いてよいのは**親子室・多目的鑑賞室のように別室にある席だけ**。車いす席は引かない。
引いたときは、出典の備考に元の数と内訳を原文で残すこと。

**「客席定員◯名（車いす用席を含む）」は客席数として採ってよい。** 親子室が別行で書かれていれば、
その数は親子室を含まない。京都市の文化会館（北・右京・西・東部）はこの形で、
調査エージェントが「内訳が無い」として採らずに見送る例が続いた。
採らないのは、親子室を含むのか判別できない場合だけでよい。

#### 親子室：客席数の内訳文に紛れている

`親子室` は独立した見出しを持たず、**客席数の内訳の末尾に紛れている**ことが多い。

> 「1,382席（1階1,056席、2階314席、1階車椅子席10席、2階車椅子席2席、**親子室**）」
> 「固定席：1,202席（オーケストラピット154席を含む）車いす席：6席、**親子室：16席**」

客席数を読むときに必ず内訳の末尾まで見て、親子室の記載があれば `親子室: true` を立てること。
2施設連続で取りこぼしたので、意識して探す。

なお内訳に席数が書かれている場合、施設概要ページの客席数と個別ページの客席数が
食い違って見えることがある（1,202 と 1,224 は 1,202＋車いす6＋親子室16 で整合した）。
**食い違いを見つけたら、まず内訳の足し算が合わないかを確かめる。**

#### 舞台幅：開口寸法と主舞台寸法を混同しない

大きなホールは「主舞台寸法 幅29.0m」と「ポータル開口 幅14.5m」のように
**2種類の幅**を書いていることがある。

`舞台幅` に入れるのは**客席から見た開口の幅**（間口 / プロセニアム開口 / ポータル開口）。
主舞台全体の物理的な幅ではない。判別できない場合は書かず、備考にどちらの記載があったかを残す。

**アリーナ形式・ワインヤード形式のホール**（「舞台を客席が360度囲む」「舞台客席一体型」など）は
プロセニアムを持たないので、**`舞台幅` は書かない**。公式に「舞台 幅◯m」と一つだけ
書かれていても、それは開口幅ではなく舞台そのものの幅であり、プロセニアムホールの間口と
並べて比較できない。備考に「アリーナ形式のため舞台幅は記録しない」と原文つきで残すこと。
`舞台奥行` はこの制約を受けないので、書いてあれば記録してよい。

#### 面積：畳数しか書いていない部屋は記録しない

民間スタジオ・和室は「10畳」「6畳弱」のように**畳数しか書いていない**ことが多い。
1畳の広さは地域や物件で違うので、**㎡へ換算して `面積` に書かないこと**（公式にない数字を作ることになる）。
畳数は出典の備考に原文で残す。㎡の表記があるときだけ `面積` を書く。

#### 部屋名：注記を混ぜない

公式が「第3会議室【会議室4とつなげて利用可能】」「ホール（平土間・移動式観覧席）」のように書いていても、
`部屋名` は「第3会議室」「ホール」とし、注記は出典の備考に残す。

練習場:

| フィールド | 型 | 備考 |
|---|---|---|
| `部屋名` | string | 必須 |
| `管楽器` / `打楽器` | boolean | 後述 |
| `楽器制限` | string | 条件・補足を原文に近い形で |

両方で使える（**ホール施設もスタジオ・多目的室を持っているのが普通**）:

| フィールド | 型 | 備考 |
|---|---|---|
| `面積` | number | ㎡ |
| `定員` | number | 人。座席のない部屋の収容人数 |

共通の備品:

| フィールド | 型 | 備考 |
|---|---|---|
| `ピアノ有無` | boolean | |
| `ピアノ種別` | string | `グランド` / `アップライト` / `電子` |
| `ピアノメーカー` | string | 型番も含めてよい。複数台なら「スタインウェイD-274・ヤマハCFX」 |
| `パイプオルガン` | boolean | |
| `オルガン製作者` | string | 「クーン社（54ストップ）」など |
| `譜面台貸出` | boolean | |
| `譜面台数` | number | 本数 |

### 設備の3値

- `true` … あると書いてある
- `false` … **無いと明記されている**場合のみ
- **キーごと省略** … 書いていない（＝未調査）

**「書いていない」を `false` にしないこと。** 混同すると、実際には設備がある施設が
利用者の絞り込みから消える。

**「料金表に載っていない」を `false` にしないこと。** 此花区民ホールの調査で、附属設備の一覧に
ピアノの記載が無い会議室を `ピアノ有無: false` と書いてきた例があった。これは「無い」ではなく
「書かれていない」なので**キーごと省略する**。`false` と書いてよいのは
「ピアノはありません」「楽器の演奏は不可」のように**否定が明記されている**場合だけ。

### 楽器の可否

- 金管・木管は分けない。まとめて `管楽器`
- **条件付きで使える場合は `true` にしたうえで、`楽器制限` に条件を書く**（`false` にしない）
  例: 「音量制限あり」「養生が必要」「木管のみ可」
- 「打楽器不可」とだけ書かれている場合は `打楽器: false` のみ。
  `管楽器` は書いていないので**省略する**

### ホール種別の判定

上から順に当てはめる。判断がつかなければ**書かない**。

1. 施設が自ら「音楽専用」「コンサート専用」「音楽主目的」のように、
   **音楽を主たる用途だと明言している** → `音楽専用`
   （「室内楽・コーラスなどのクラシック音楽を最適の音響特性で演奏・鑑賞できる音楽主目的ホール」も該当する）
2. 客席数がおおむね300席未満で、リサイタル・室内楽向け → `小ホール・サロン`
3. プロセニアム形式で緞帳・舞台機構を持ち、音楽以外（演劇・式典）にも使う → `多目的`
   **音響反射板が「可動式」「設置式」と書かれていれば多目的の目印**

### 出典

```yaml
出典:
  - URL: https://example.com/about/     # 値の裏が取れたページ
    確認日: '2026-08-11'                 # 調査日
    項目: [客席数, 舞台幅]                # このURLで確認できたフィールド名
    備考: 楽屋の収容人数は記載なし         # 確認できなかった点・不確かな点
```

複数ページを見たなら、ページごとにエントリを分ける。

## 報告

出力ファイルを書いたうえで、次を簡潔に報告する。

- 見たページのURL
- 確認できた項目
- **見つからなかった項目**（これが重要。「調べたが無かった」と「調べていない」は違う）
- 公式サイトの記載に矛盾・不審な点があればその内容
