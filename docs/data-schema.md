# 施設データのスキーマと記述ルール

YAML（`data/facilities/`）の書き方。**施設データを足す・直すときはここが正。**

手順は [CONTRIBUTING.md](../CONTRIBUTING.md)、作業の入口は [CLAUDE.md](../CLAUDE.md)（索引）。

## Data Schema (YAML)

施設データは日本語キーのYAMLリスト形式で記述する。ファイルは `data/facilities/` 以下に用途別で管理する。
**1レコード = 1施設**（コンサートホール・練習場とも同じモデル）。

**共通フィールド（両YAMLファイル）:**

```yaml
- ID: number                   # 必須（URLに使用: /concert/:id, /practice/:id）
  施設名: string               # 必須
  施設名かな: string           # 漢字を含む施設名では必須（五十音順ソート用・ひらがな）
  都道府県: string             # 必須 例: 大阪府, 京都府, 兵庫県 など
  市区町村: string             # 必須（政令市は区まで／郡部は郡名から 例: 神戸市中央区, 佐用郡佐用町）
  番地以下: string             # 必須（半角数字・半角ハイフン）
  建物: string                 # 任意（ビル名・階・部屋番号）
  TEL: string                  # 任意
  開館時間: string             # 任意（"HH:MM" 24時間表記 例: "09:00"）
  閉館時間: string             # 任意（"HH:MM" 例: "22:00"）
  休館日: string               # 任意
  URL: string                  # 任意
  申込URL: string              # 任意
  料金URL: string              # 任意
  駐車場: number               # 任意（台数）
  最寄駅:                      # 任意（配列）
    - 種別: string             # 任意（駅 / バス停）省略＝駅
      路線: [string, ...]      # 任意。同一駅に複数路線が乗り入れる場合は並べる
      駅: string               # 必須
      出口: string             # 任意 例: ⑥号出口, 南改札口
      駅徒歩: number           # 任意（分）公式が徒歩分数で書いている場合
      駅距離: number           # 任意（m・道路距離）公式が距離で書いている場合
  貸館:                        # 任意。**通常どおり貸している施設では書かない**
    状態: string               # 必須（休止 / 終了 / 予定 / 廃止）
    開始: 'YYYY-MM'            # 任意（予定 では未来の月になる）
    再開: 'YYYY-MM'            # 任意（休止・予定のみ。未定なら省略）
    理由: string               # 任意 例: 大規模改修工事, 貸館業務終了
  利用条件:                    # 任意。**誰でも借りられる施設では書かない**
    種別: string               # 必須（公募選考 / 資格限定 / 要紹介）
    説明: string               # 必須。公式の記載に沿った説明
  ピアノ有無: boolean          # 任意（部屋に紐付かない貸出備品の場合のみ）
  譜面台貸出: boolean          # 任意（同上）
  譜面台数: number             # 任意（本数が分かる場合）
  出典:                        # 任意（配列）
    - URL: string              # 必須（値の裏が取れたページ）
      確認日: 'YYYY-MM-DD'     # 必須（クォート付き）
      項目: [string, ...]      # 任意。このURLで裏が取れたフィールド名
      記載なし: [string, ...]  # 任意。このURLを確かめたが、値を確定できる記載が無かったフィールド名
      備考: string             # 任意。確認できなかった点・不確かな点
  検査除外:                    # 任意。確かめたうえで受け入れた警告（画面用のJSONには出ない）
    - 警告: string             # 必須。警告の種類（出力の見出しと同じ文言）
      対象: string             # 任意。警告の詳細の書き出し 例: 最寄駅[1]。省くとその種類をすべて抑止
      理由: string             # 必須。何を確かめて受け入れたのか
  経度: number                 # 必須
  緯度: number                 # 必須
```

**`concerthall.yaml`（コンサートホール）固有フィールド:**

```yaml
  築年月: string               # 任意（YYYY-MM形式 例: 1995-04）
  部屋:                        # 任意（配列）＝施設内の各ホール
    - 部屋名: string           # 任意（単一ホールの施設では省略可）
      ホール種別: string       # 任意（音楽専用 / 多目的 / 小ホール・サロン）
      客席数: number           # 任意
      面積: number             # 任意（㎡）スタジオ・多目的室など座席のない部屋
      定員: number             # 任意（人）同上
      楽屋収容人数: number     # 任意（合計人数。部屋数では実態を表せないため）
      舞台幅: number           # 任意（m）
      舞台奥行: number         # 任意（m）
      管楽器: boolean          # 任意（併設の音楽練習室など）
      打楽器: boolean          # 任意
      楽器制限: string         # 任意
      ピアノ有無: boolean      # 任意
      ピアノ種別: string       # 任意（グランド / アップライト / 電子）
      ピアノメーカー: string   # 任意
      チェンバロ: boolean      # 任意
      パイプオルガン: boolean  # 任意
      オルガン製作者: string   # 任意（例: クーン社（54ストップ））
      譜面台貸出: boolean      # 任意
      譜面台数: number         # 任意（本数が分かる場合）
      親子室: boolean          # 任意
      記載なし: [string, ...]  # 任意。この部屋について、公式に記載が無かった項目（→ 記述ルール）
      貸館:                    # 任意。**その部屋だけ休止・終了している場合**（施設の 貸館 より優先）
        状態: string           # 必須（休止 / 終了 / 予定 / 廃止）
        開始: 'YYYY-MM'        # 任意
        再開: 'YYYY-MM'        # 任意（休止のみ）
        理由: string           # 任意
```

```yaml
      打楽器: boolean          # 任意
      楽器制限: string         # 任意（条件・補足。条件付き可なら true ＋ ここに条件）
      ピアノ有無: boolean      # 任意
      ピアノ種別: string       # 任意（グランド / アップライト / 電子）
      ピアノメーカー: string   # 任意
      チェンバロ: boolean      # 任意
      譜面台貸出: boolean      # 任意
      譜面台数: number         # 任意（本数が分かる場合）
      記載なし: [string, ...]  # 任意。この部屋について、公式に記載が無かった項目
      貸館:                    # 任意。その部屋だけ休止・終了している場合（施設の 貸館 より優先）
```

## 記述ルール

- **設備の3値**: `true`＝あり、`false`＝なし、**キーごと省略＝未調査**。
  `false` を「未調査」の意味で使わない。混同すると、実際には設備がある施設が絞り込みから消える。
  `〇` / `×` を書くと `build-data.mjs` がビルドを止める。
  **未調査は「無い」ではないという扱いは、boolean 以外の項目にも及ぶ**
  （客席数・定員・徒歩分数などの未記入も、絞り込みでは「合わない」ではなく
  「判断できない」として数え、件数を利用者に開示する。→ `src/filter.ts`）
- **備品は「有無(boolean) ＋ 詳細(任意)」で持つ**。`ピアノ有無`＋`ピアノ種別`/`ピアノメーカー`、
  `譜面台貸出`＋`譜面台数`。詳細だけあって有無が立っていないとビルドが止まる。
  「あるが本数・種別が不明」を表せるようにするための形
- **楽器の可否**: 実際の施設で区別されているのはほぼ「打楽器」だけなので、
  **金管・木管は分けず `管楽器` にまとめる**。細かい区別や条件は `楽器制限` に文章で書く。
  **条件付きで使える場合は `true` にしたうえで `楽器制限` に条件を書く**（`false` にしない）
- **借りられない施設は `貸館` を立てる**。状態は4つ。
  `休止`＝改修などで一時的、`終了`＝貸館事業そのものを終えた（用途変更・閉館を含む）、
  `予定`＝**まだ借りられる**が休止・終了が告知されている、`廃止`＝施設そのものが無くなっている。
  既存の `休館日` は毎週の定休日を指すので語がぶつからないよう `貸館` で束ねている。
  **建物は開いていても貸館だけ終えている施設がある**ため「閉館」とは呼ばない。
  通常どおり貸している施設ではキーごと省略する。
  **`予定` を `休止` と同じに扱わない。** ホールの予約は12か月前から取るので、
  休館が先でも利用者には必要な情報だが、今日借りられる施設を「休止中」と見せてはいけない。
  開始月が来たら `休止` か `終了` に直す（検査スクリプトが期限切れの `予定` をエラーにする）。
  **`廃止` は `終了` と違い、施設が現に在るかどうかの区別**（葺合文化センターは建物ごと解体、
  堀江アルテは公式サイトが消え何年も活動の記録が無い）。告知が無く状況証拠だけで判断したときは
  その旨を `理由` に必ず書く。
  **一部の部屋だけ休止・終了している場合は、施設ではなく `部屋` 側に書く**
  （施設側の `貸館` は「全室が対象」の意味。部屋側があればそちらが優先される）。
  あましんアルカイックホールは大ホールが休止・中ホールが営業中・小ホールが終了と3つに分かれる
- **借りられる人が限られる施設は `利用条件` を立てる**。`貸館` は休止・終了を表すものなので、
  「今も貸しているが、誰でも借りられるわけではない」を書く場所が別に要る。種別は3つ。
  `公募選考`＝時間貸しをしておらず公募・審査で利用者を選ぶ（京都芸術センター）、
  `資格限定`＝条例などで利用者の資格が限られる（難波市民学習センターは生涯学習団体のみ、
  豊中市立公民館は市内在住・在勤・在学者が5割以上）、`要紹介`＝紹介者が要る（フィガロホール）。
  **市外料金が高い・登録すると減免になるといった料金の差は利用条件ではない**（誰でも借りられる）。
- **部屋に紐付かない備品は施設レベルに書く**。`ピアノ有無` / `譜面台貸出` / `譜面台数` は
  施設にも部屋にも書ける。受付で申し込む貸出備品として扱われ、どの部屋に置かれるか公式に
  書かれていない施設があるため（千里山コミュニティセンター）。**置かれる部屋が決まっているなら
  部屋側に書く**（施設レベルに書くと、どの部屋でも使えるかのように見えてしまう）。
- **音楽に使えない部屋はビルド時に除外される**。会議室・和室・調理室のように、
  音楽設備（ピアノ・譜面台・管楽器・打楽器・楽器制限・パイプオルガン・チェンバロ）も
  客席数・舞台寸法・ホール種別も無く、部屋名も音楽用と読めない部屋は
  `build-data.mjs` が JSON に出さない。**YAMLからは消さない**（調査した事実と出典は残す）。
  判定は「落としてよいと言い切れるか」で、迷えば残す側に倒している
  （ピアノが1台でもあれば会議室でも残り、設備が未調査の練習室も名前で残る）
- **`管楽器` / `打楽器` / `楽器制限` は両ファイルの `部屋` で使える**。
  コンサートホール施設が音楽練習室を併設している例（文化パルク城陽）があるため
- **予約方式・市外料金は持たない**。変わりやすいため `申込URL` / `料金URL` の参照に委ねる
- **残響時間は持たない**。掲載している施設が半分程度しかなく欠損だらけになる。
  残響が示す「音楽向きか多目的か」は `ホール種別` で代替する
- **ホール種別は画面に出していない**（一覧の絞り込みとカードのチップを外してある。
  詳細ページの部屋の表には残っている）。「多目的」の語が平土間の多目的室を連想させ、
  反射板を持ちオーケストラを想定した劇場型ホール（市民会館の大ホール）と区別できないため。
  区分の用途を整理し直すまでの措置で、YAML・型・`filterHalls` の条件は残してある。
  一覧はURLの `type=` も読み捨てる（見えない条件で絞らないため）。
  区別の目印の候補は `音響反射板` の有無
- **ホール種別の判定**は上から順に当てはめる。判断がつかなければ設定しない:
  1. 施設が自ら「音楽専用」「コンサート専用」と称している → `音楽専用`
  2. 客席数がおおむね300席未満でリサイタル・室内楽向け → `小ホール・サロン`
  3. プロセニアム形式で緞帳・舞台機構を持ち音楽以外にも使う → `多目的`
     （**音響反射板が可動式・設置式であることが実務上の目印**）
- **ピアノが複数台ある場合**（ホールでは普通）は `ピアノ種別` に代表的な種別を、
  `ピアノメーカー` に「スタインウェイD-274・ヤマハCFX」のように並べて書く
- **練習場に用途の分類は持たない**。「オーケストラ用/アンサンブル用」は主観的なので、
  部屋の `定員` から一覧側で絞り込む
- **公式に書かれていなかった項目は `出典[].記載なし` に挙げる。** 施設のサイトは無いものを
  まず書かないので、調べても埋まらない項目が多い（ピアノ有無の記入はほぼ全部が `true`）。
  キーの省略だけでは「調べていない」と区別がつかず、調べに行く先も、利用者への説明も分からない。
  - **記載なしは `false` ではない。** 絞り込みでは未調査と同じく「判断できない」に数える
  - 書けるのは施設の TEL・開館時間・閉館時間・休館日・駐車場・築年月と、部屋の項目
    （`transform.mjs` の `NOT_STATED_*_FIELDS`）。知らない項目名はビルドが止まる
  - **1室だけの話なら `部屋[].記載なし` に書く**（「小スタジオBのピアノの記載は無い」）。
    出典に書くと値の無い部屋すべてに配られる。出典に書くのは施設全体・全室についての話
  - **駐車場は、駐車場に触れていないときだけ。** 「駐車場あり（台数の記載なし）」は記載なしにしない
    （画面に「公式に記載なし」と出ると、駐車場が無いか分からないように読める）
  - **貸出品目の一覧に無いことは、楽器の可否の記載なしではない。** 管楽器・打楽器は
    「持ち込み・演奏の可否」が書かれていないときに挙げる（譜面台は貸出そのものなので挙げてよい）
  - 判断で決める `ホール種別` は挙げない（公式が書く値ではない）
  - `build-data.mjs` が**値の無い**施設・部屋に `記載なし` として配る（値のある部屋には付かない）。
    詳細ページは部屋の設備欄に「記載なし」、情報表に「公式に記載なし」と出す
  - 一部しか書かれておらず値を確定できないもの（楽屋の一部の人数が無い）も記載なしに入れ、事情は `備考` に書く
  - 再調査で値が分かったら記載なしから外す。値の埋まった項目が残っていると警告が出る
- **出典**: 値の裏を取ったURLと確認日を必ず残す。LLMによる自動収集は誤りを含むため、
  出典のないデータは未検証として扱う（詳細ページに「出典・確認日は未記録です」と表示される）。
  **詳細ページに出すのは最終確認日だけ**で、出典のURL・備考は画面に出さない（データには残る）
- **住所**: `市区町村` は市・区・町・村レベルまで（政令市は区まで、郡部は郡名から）。
  `番地以下` は半角数字・半角ハイフンに統一し、都道府県・市区町村を重複させない。
  **ビル名や階数は `建物` に分ける**（`番地以下` に混ぜるとジオコーディングでの座標検算が効かなくなる）。
  以上は `build-data.mjs` が検査し、違反するとビルドが止まる
- **施設名かな**: ひらがなで書く。**括弧内の別名は読みに含めない**
  （例: `ラブリーホール（河内長野市立文化会館）` → `らぶりーほーる`）。
  かな・カナだけの施設名はビルド時に導出できるので省略してよい。
  漢字を含むのに未設定だと警告が出る（五十音順に並ばず、末尾のグループに送られる）
- **時刻**: `"HH:MM"` の24時間表記・ゼロ埋め・クォート付き。
  `開館時間` は**施設の開館時間**であって、貸館受付やチケット窓口の営業時間ではない
- **駐車場**は施設の駐車場のみ。近隣の公共駐車場や搬入トラック用スペースは含めない
- **駅徒歩 / 駅距離**: 公式サイトに書いてある方だけを書く（両方あれば両方）。
  `駅距離` のみの場合、`build-data.mjs` が **道路距離80m＝徒歩1分・端数切り上げ**
  （不動産の表示に関する公正競争規約に準拠）で `駅徒歩` を補完し、`駅徒歩推定: true` を付ける。
  逆方向（徒歩→距離）の補完は行わない
- **駅距離は道路距離**であって直線距離ではない
- **バス停は `種別: バス停` を立てる**。鉄道駅から歩けない施設（守山市民ホールは守山駅から
  徒歩30分で、公式もバス案内）があるため最寄駅として載せるが、**バス停は鉄道の駅ではないので
  駅名の語尾検査にも駅座標マスタの照合にもかけない**（かけると必ず「見つからない」になる）。
  名前が「◯◯バス停」「◯◯停留所」で終わるものは名前から判別できるので省略してよい。
  書くのは「しづかホール前」「出戸バスターミナル」のように**名前では鉄道駅と区別がつかない**もの。
  一覧・詳細では「出戸バスターミナル（バス停）」と表示され、電車で行けると誤解されないようにする
- **駅徒歩が駅距離より短いときだけ警告する。** 80m/分は健脚の基準で、公式は坂道・信号・
  地下通路を織り込んで長めに書く（いずみホールは600mに徒歩10分）。
  **公式が換算より長いのは正常**なので警告しない。両方向を疑うと常時ノイズになり、
  本当に見たい「実際より近く書かれている」が埋もれる
- **公式どおりに書いた値が警告に掛かるときは `検査除外` を書く。** 値を検査に合わせて書き換えない
  （出典と値が食い違う）。トレピエは公式が「1.8km（約20分）」と書き、換算の約23分と合わない。
  **`理由` は必須**で、何を確かめたかを残す。抑止した件数は `npm run data` の末尾に出る（中身は `--verbose`）。
  **どの警告にも当たらなくなった除外は「使われていない検査除外」として警告になる**
  （データを直したのに除外だけ残ると、次に出た本物の警告まで黙って消えるため）。
  データの誤りを黙らせるためには使わない
- **ID**: **一度振ったら絶対に変更しない**。`/concert/:id` `/practice/:id` としてURLに使われるため、
  変更すると外部からのリンクが切れる。
  - 欠番があってよい（施設を削除したり統合したりした結果の欠番はそのまま残す）
  - **並び順に意味を持たせない。** レコードを並べ替えてもIDは振り直さない
  - 新規は「そのファイルの最大ID + 10」を振る。10刻みは挿入余地を残すための慣習
  - IDの名前空間はファイルごと。`concerthall` の ID:30 と `practice` の ID:30 は別施設で、
    URLのパス（`/concert/` `/practice/`）で区別される。接頭辞は付けない
  - **同じ施設を両方のファイルに載せない。** IDの名前空間が別なので、ID の重複検査では
    気づけない（阿倍野区民センターは練習場からコンサートホールへ「移した」もの）。
    施設名が重なると検査が警告する（同じファイルの中での重複も同じく。1レコード = 1施設）
