# 鮮度確認（件数指定）

**手順の正は [docs/freshness-check.md](../../../docs/freshness-check.md)。** まずそれを全部読み、そのとおりに動く。
このスキルが変えるのは **件数だけ**。ほかの手順（子は Haiku・親が裏取り・PR の題名と本文）はそのまま。

## 件数

引数: `$ARGUMENTS`

- 引数の先頭の正の整数を件数 N とする。空なら **N = 10**（定期実行と同じ）
- 数字として読めない引数なら、推測せずに件数を利用者に尋ねる
- **N が 20 を超えるときは、始める前に利用者に確認する。**
  10件で5時間枠の約14%と見積もっているので、件数に比例して使用量が増える（20件で約28%）
- 対象が N 件に満たないとき（飛ばす施設を除いた `stale` が足りない）は、ある分だけ確認し、
  件数が減ったことを PR 本文と報告に書く

## 手順書との対応

| 手順書の節 | このスキルでの扱い |
| --- | --- |
| 2. 対象を選ぶ | 「先頭から10件」を **先頭から N 件** と読み替える。飛ばす条件は同じ |
| 3. 子に調べさせる | 1施設に1つ、N 個の Haiku サブエージェントを並行で立てる。N が大きいときは10個ずつに分けてよい |
| 6. PR を出す | 題名の `（N件）` には **実際に確認した件数** を入れる |

## 対話で回すときの違い

- ブランチ: セッションで指定されたブランチがあればそれを使う（`claude/` で始まる名前であること）。
  無ければ `claude/freshness-YYYY-MM-DD` を切る
- 途中で使用量の上限に当たったら、定期実行と同じく **PR を出さずに終え**、どこまで進んだかを利用者に伝える
- 終わったら、PR の URL と「直した件数・人の判断が要る件数・退けた主張の件数」を短く報告する
